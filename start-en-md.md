## 🔥 WORK RULES

### 📱 Communication

#### 1. Text Only, No Audio

**Why:** Audio steals time. A 3-minute audio = 3 minutes of listening + impossible to quickly find info later. Text is read in 20 seconds and always at hand. You won't have to re-listen to 5-minute rambling speeches to understand the task.

We work asynchronously.
* No one will call you on the weekend.
* No one demands an instant response within 5 minutes.
* You work in your timezone, we work in ours. Meeting point — GitHub.

#### 2. Write Immediately with Context

❌ **Bad:** "Hi", "Not working", "Can I ask a question?"

✅ **Good:** "Preparing build for App Store. Error: 'Invalid Bundle ID'. Screenshot: [link]  
Checked: bundle ID = com.greatapp.auth, provisioning updated. Question: is this ID registered in your Apple Developer account?"

**Message Structure:**

1. What are you trying to do?
2. What exactly isn't working?
3. Screenshot/code/link
4. What have you already tried?
5. Specific question

**Why:** We save 5-10 back-and-forth messages. A colleague in a different timezone will immediately understand the problem and respond in one go.

#### 3. Prohibited:

- **Passive aggression:** "well ok...", ellipses
- **"Can I ask a question?"** — just ask the question
- **"Bottom left"** — send a screenshot with an arrow
- **Files in DM** — only links to cloud/GitHub

**Why:** We respect each other's time.

#### 4. Use Emojis for Statuses

👍 = read | ✅ = done | 👀 = looking

**Why:** Quick feedback without unnecessary words.

---

### 💼 Work Process

#### 5. Everything in GitHub Issue

No task in GitHub Issue = task doesn't exist. All discussions there, not in DM. Task reminders — in Discord.

**Why:** Decision history is preserved. The specification describes in detail what needs to be done.

#### 6. Response Within 4 Hours During Working Hours

Don't expect an instant response, but don't disappear for long either.

**Why:** Focused work is important, but in 10 days we can't lose time waiting.

#### 7. Daily Status is Mandatory

Every day — brief status in Discord.

**Example:**
```
✅ Day 3: Auth screen + main screen ready. Tomorrow: settings
```

We don't micromanage. 1-2 sentences are enough + screenshot of completed screens.

**Why:** In 10 days it's easy to "lose" 2-3 days unnoticed.

#### 8. Progress Screenshots Are Mandatory

Every completed screen = screenshot in GitHub Issue.

**Why:** Visual work = visual control. You can immediately see what's done. We're not perfectionists — usually we approve 90% of submissions immediately, except for critical bugs.

#### 9. Calls Are a Last Resort

First, 1-2 attempts to solve via text. If a call is needed — send an agenda with questions in writing. Meetings without an agenda = prohibited.

**Why:** Call = everyone drops their work. But sometimes it's easier to have a call and resolve the issue, especially if it's critical. But without an agenda there will be no call.

### ⏰ Deadlines and Emergency Situations

#### 10. For Urgent Questions — Discord

If there's no response to an issue for a long time — write in Discord.

**Why:** Real urgent situations sometimes happen.

#### 11. Weekends = Weekends

Sunday — always a day off.

**Why:** Burnout kills productivity. A rested person works 3 times better.

We value long-term relationships, but there are things we don't work with:
